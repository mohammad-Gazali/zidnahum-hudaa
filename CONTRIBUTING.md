# Contributing

This document records the rules that keep the codebase coherent. They are deliberately short — the durable decisions, not the day-to-day details (see `AGENTS.md` for project layout, commands, and conventions).

## The promotion rule (where code lives)

**Code starts in the feature that needs it, and only moves to `shared/` when a second feature genuinely needs it too.**

- New service/pipe/component → put it under the feature (`@client/*` or `@admin/*`) that uses it.
- Only promote to `src/app/shared/` the moment a real second consumer appears.
- `src/app/shared/services/` must never silently refill with single-feature code — that is a regression, not an improvement.

When auditing placement, judge by **actual cross-feature usage today**, not by anticipated future use. A service used only by one feature belongs in that feature. Moving a service that a shared pipe depends on (e.g. `MemoService` behind `MemoPipe`, `TestService` behind `TestPipe`) is usually a sign you should move the pipe too — never leave a shared → feature import behind.

## Generated code

`frontend/src/app/shared/services/api/` is **100% generated by Orval** (`bun generate:services`). Never hand-edit generated files — the fix belongs in the backend schema/tags. See `frontend/src/app/shared/services/api/README.md` for the full rule. The only intentional exception is `report-export.service.ts`, documented in its own header.

## Loading state

There is exactly **one** global loading signal: the `LOADING` injection token (`frontend/src/app/shared/tokens/loading.token.ts`). Components that need to gate on a busy state inject it directly (`inject(LOADING)`). Do not add private/second loading signals; a component that needs per-item progress should use its own local signal only for that per-item state (e.g. `loadingIds`), not for the global busy state.

## TypeScript & style

- Single quotes, strict mode, `@shared` / `@admin/*` / `@client/*` path aliases.
- Generated enum models (`MasjedEnum`, `StudentLevelEnum`, `MessageTypeEnum`) are canonical — import enum members by SCREAMING_SNAKE keys and never re-declare duplicates.
- Run `npx tsc --noEmit -p tsconfig.app.json`.
